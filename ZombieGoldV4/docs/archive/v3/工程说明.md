# 《末日突围 · V3 撤离体验版》工程说明

本版以 README、项目说明、策划案中的 V3 定义为准。最新新增文件：content/experience.js 统一覆盖旧关尾、鱼牌和关卡叙述；sim/extraction.js 提供纯撤离模拟与明确奖励；view/extractionview.js 提供接应平台/车辆/红区/信标/HUD；ui/missionui.js 提供路线和撤离报告。Game.startExtraction 接 runDone，extractionEnd 发放奖励并结算，支持编辑器隔离和医疗。旧捕鱼/开奖模块留作历史参考但不进入本版主流程。下文沿用的底层模块说明仍可查，旧末日战场、翻牌和剧本部分不是 V3 的实际流程。

给接手的程序看：东西在哪、数据怎么走、想改什么去哪改、怎么测、怎么调试、怎么打包。引用一律写「文件 + 函数 / 导出名」，不写行号。

玩法规则和每版决定看 `docs/策划案.md`；美术素材看 `docs/素材清单.md`；每版改了什么看 `docs/改动记录.md`；关卡 JSON 格式看 `docs/关卡配置格式.md`；和主 App 的对接看 `docs/接入方案.md`。

## 1. 这是什么

以 V9.5 的数字门、自动射击和金币为基础，新增三种行动、营救与物资结算、避难所设施和支援。敌人、Boss 与主角使用交付的 Spine。第一版忠实换皮在同级 ZombieGold；第二版的新增内容改变了实际队伍、敌人和收益。

来源历史保留在第一版副本；第二版是独立目录，没有复制 .git，没有推送。

## 2. 怎么跑

- 纯静态 ES module，**没有打包步骤，不用装任何东西**。在仓库根目录起任意静态服务器：

  ```bash
  python3 -m http.server 8018 --bind 127.0.0.1
  ```

  打开 http://127.0.0.1:8018/ 。需要联网：three.js r160 从 jsDelivr 拉（`src/view/three.js` 是唯一固定版本的地方），字体走 Google Fonts。
- Spine 运行库是经典脚本 `vendor/spine-3.6/spine-webgl.js`，`index.html` 在模块之前加载它（全局变量 `spine`）。
- 新存档进入 1-1 行动选择；每关先选营救/搜刮/撤离。避难所从第一关即可查看，期间游戏暂停。末日战场仍等 3-3 解锁；提前看地图可点左上菜单。
- 键盘：←→ / A D 移动队伍；按住空格加速一档；末日战场里 ↑↓ / W S 调炮倍。
- 素材预览：http://127.0.0.1:8018/tools/spine3d.html （见第 8 节）。

## 4. 一关的数据怎么走

**配置 → 逻辑 → 事件 → 接线 → 画面 / 界面 / 声音 / 金币。**

1. `src/content/levels.js` 的 `LEVELS[i]`：`run.seq` 是积木序列（如 `['g', '+20', 'x2', { post: true }]`、`['w', 8, 10]` 尸潮、`['mb', 900, 20, '运钞怪']` 小 Boss），`finale` 写 Boss 和结尾惊喜。
2. `Game.start(i)`（`src/game.js`）：等这个大关的素材（`prepareCast`），建 `new RunSim(level, emit, scale, { seed })`、`World.buildLevel`、`new RunView(...)`。
3. `RunSim.update(dt)` 每帧推进，阶段是 `ready → run → arrive → boss → done / fail`，结尾惊喜时是 `finale`。发生的事都用 `emit(k, d)` 报出来（`gate`、`count`、`zdie`、`barrel`、`bossSpawn`、`bossDie`、`runDone`、`finHit`、`finaleEnd`、`fail` 等约 70 种）。
4. `Game.onRun(k, d)` 是一个大 switch：每个事件分到 RunView 的一次性特效（`onGate`、`onZombieDie`…）、UI（`banner`、`floatWorld`）、声音（`sfx`）和钱（`save.wallet`、`game.R`）。**这个 switch 就是表现层的需求单。**
5. `RunView.update(dt, labels)` 每帧读 sim 状态摆角色；数字飘字、血条、兵数标签是 DOM（`ui.js`）。
6. Boss 打完，`runDone` 按 `finale.after` 走：兑换门 `startExchange`、结尾转盘 `pickSurprise`、结尾惊喜 `startSurprise(type)`、黄金尸池 `startLoad`；最后 `finishLesson` 记进度、出结算。

**钱不在逻辑里。** sim 只报倍数和单位，加钱在 game.js：`payKill`、`runCoins`、`payFinale`、`updateLoad`（兑换门）、`bossDie` 分支。一星按剧本给钱：`startSurprise` 先算这局打得怎样（`perf`），再给结尾的每个单位定价，让一关总收入落在「剧本 × 表现系数」附近。

## 5. Spine 角色怎么进游戏

```
美术交付（收件箱）──tools/import_spine.py──▶ assets/spine/<分组>/<编号>/ + catalog.json
                                                │
src/content/cast.js（演员表：谁演谁、多高、动作名）│
                                                ▼
src/view/cast.js  prepareCast(大关) 读骨骼 ──▶ crowdBook()：兵和尸潮烘焙成一张图集（SpriteCrowd 一次画完）
                                          ──▶ Rig / SpineActor：Boss、小 Boss、主角，实时骨骼
                                          ──▶ targetCard()：DOM 用的头像
```

- **成群的角色**（兵、尸潮、精英、伏击、盾墙、蝙蝠、末日战场的小僵尸）：进关时把每个动作按帧烘焙进一张 2048² 图集（`bakeFlipbook`，约 0.1～0.2 秒），之后每个角色只是一个面片，`SpriteCrowd.put(类型, 动作, 时间, x, y, z, 朝向, 大小, 染色, 透明, 倾斜, 闪白)`。按远到近排序，一次画完。
- **单个的大角色**（Boss、小 Boss、末日战场的主角和大目标）：`SpineActor` 每帧更新骨骼，画质最好。
- **都是面向镜头的纸片**（billboard），脚踩地面；美术的僵尸都朝左，代码按移动方向镜像。
- 贴图是预乘透明度（PMA），所有材质都用 (ONE, ONE_MINUS_SRC_ALPHA) 混合；加色叠加的部位用透明度 0 实现，同一种混合就能画完整个骨骼。
- 角色不受场景灯光影响，`SPRITE.light`（`spine/material.js`）跟着场景调亮度，夜里的关卡会暗一些。
- 美术的阴影槽（名字是 `yy` / `shadow`）照画；没有自带阴影的角色，人群会在脚下补一个软阴影。

## 8. 调试

### 网址参数（`src/main.js` 读）

| 写法 | 作用 |
|---|---|
| `#debug` | 实验室面板里多一个「调参台」按钮；`window.__gf` 一直都有 |

### `window.__gf`

| 名字 | 是什么 |
|---|---|
| `game` | `Game`：`game.start(i)` 开第 i 关（从 0 数）；`game.bot = 'best' \| 'mostly' \| 'random'` 开自动驾驶；`game.sim` / `fsim` / `bsim` 是当前的逻辑 |

| `hold` | 设 `true` 冻结游戏时钟 |
| `ff(sec)` | 按 1/60 秒一步快进（不渲染），预览窗口在后台时用它推进 |
| `snap(name)` | 渲染一帧，把 3D 画布 POST 到开发服务器的 `/capture` |

### 开发脚本

- `tools/devrun.js`（控制台 `const m = await import('/tools/devrun.js')`）：`runLevel(i, bot)` 自动驾驶跑一关并报收入分项；`runAll`、`goTo`、`gateReport`、`regress`（固定种子的回归对比）。
- `tools/spine3d.html`：素材预览。列出全部 Spine 素材和它在游戏里演谁；`#key=batch2/41300004` 看单个、点按钮切动作；`#lineup=k1,k2,…` 并排比大小；`#crowd` 看成群烘焙的效果和帧率。

## 9. 美术新交了一批 Spine 素材

1. `python3 -I tools/import_spine.py <收件箱目录>`：把每个骨骼拷到 `assets/spine/<分组>/<编号>/`，二进制骨骼（`.skel.bytes`）转成 JSON（`tools/skel2json.py`），重写 `assets/spine/catalog.json`。新的收件箱分组名要先加进脚本里的 `GROUPS`。
2. 打开 `tools/spine3d.html` 看新素材，记下动作名。
3. 在 `src/content/cast.js` 给它一个角色。
4. `./tests/run.sh`，再进游戏看。
5. 在 `docs/素材清单.md` 记一笔。

注意：素材必须是 Spine **3.6** 导出（运行库 `vendor/spine-3.6/` 是 3.6，3.7 以上读不了）。正式上线需要公司持有 Spine 编辑器授权（见 `vendor/spine-3.6/README.md`）。

camp 包含 parts/people/level/medkits/runs/wins/claimed。三版互不迁移，不保存关卡现场。Campaign.choose 生成行动编号；configure 克隆关卡；begin 加护盾；event 记实际打破的笼子和箱子；finish 调 settleExpedition 并 persist。Game.finishLesson 把结果带到 UI。编辑器 start 的 edit 标志跳过 campaign；runBatch 最后恢复整份 save 和持久化。

`src/platform/bridge.js` 是和宿主（主 App 和服务器）唯一的接缝：宿主在启动前定义 `window.GateFishHost`，实现 `track`、`runResult`、`openFishing`、`wallet` 中任意几个；没实现的走本地逻辑，所有调用都带超时，不会卡住游戏。合同见 `docs/接入方案.md`。`openFishing` 返回 `true` 表示宿主接管，跳到真正的目的地（二人捕鱼或之后定的产品）；否则用 demo 自带的末日战场。

## 12. 已知的债（按值得做的顺序）
