# 末日版与宿主的接缝（保留 API 兼容）

V3 更新：本版只保留突围与撤离，未调用 openFishing，不提供旧僵尸捕鱼入口。下方接口是继承的历史技术参考；未来狙击形式的捕鱼待用户另行定义，不能据此直接接入旧玩法。runResult 的 coins 现在来自清敌/回收与明确撤离公式，不含旧关尾剧本、金蛋、转盘或宝箱翻牌。

给主游戏客户端、服务器、数据三方排期用。客户端这边已经把所有对外调用收在 `src/platform/bridge.js` 一个文件里。主游戏只要在页面启动前定义 `window.GateFishHost`，实现下面用得到的方法，就能接上；没实现的方法会自动走本地逻辑，原型照样能玩。

## 1. 嵌入方式

| 方式 | 适合 | 说明 |
|---|---|---|
| WebView 内嵌 H5（推荐） | 2 人捕鱼是原生 App | 在 WebView 注入 `window.GateFishHost`，方法内部转成原生 JS Bridge 调用 |
| 同一个 H5 工程 | 捕鱼本身是 H5 / Cocos Web | 直接在同一页面里定义 `GateFishHost` |
| 独立网页 | 投放落地页 / 试玩广告 | 不定义 `GateFishHost`，走本地存档；结束页引导下载 |

## 2. 客户端接口（`window.GateFishHost`）

| 方法 | 什么时候调 | 主游戏要做什么 | 超时 |
|---|---|---|---|
| `wallet() → Promise<number>` | 启动时 | 返回服务器上的金币余额，覆盖本地钱包 | 3 秒，超时用本地 |
| `runResult(r) → Promise<{ok}>` | 每关结束 | 服务器校验后入账（见第 3 节） | 4 秒，不阻塞结算页 |
| `openFishing(ctx) → boolean` | 玩家从避难所进入末日战场 | 返回 `true` 表示主游戏接管，跳到真正的 2 人捕鱼房间；返回 `false` 时用原型自带的末日战场 | 同步 |
| `track(event, props)` | 关键时刻 | 转发给数据平台（事件表见第 5 节） | 不等待 |

`openFishing` 的 `ctx` 包含 `wallet`（当前金币）和 `items`（`bullet` 免费子弹卡、`torpedo` 爆破弹、`lock` 锁定卡的数量）。道具在跑关里获得，在捕鱼里使用，所以主游戏需要认这三种道具，或者把它们换算成主游戏已有的道具。

## 3. 服务器：跑关结果校验

`runResult` 的内容：

```json
{ "code": "2-3", "win": true, "reason": "",
  "soldiers": 1901, "shots": 9505, "peak": 2107, "kills": 132,
  "coins": 1203969, "ms": 61234, "gates": 9, "firstClear": false }
```

跑关的 RunSim/FishSim/BonusSim 已支持注入 Rng，纯逻辑相同种子可重现。但 Game 的流程、结尾定价与 DOM 开奖尚未完全抽离，也未记录完整玩家输入；不能把当前 demo 当作已经实现服务端确定性校验。`runResult` 只是异步通知，当前没有拿响应余额重新同步。正式接入前需明确服务器权威、首通唯一性和幂等交易 ID。

## 4. 账号和存档

| 数据 | 现在（本地） | 接入后 |
|---|---|---|
| 避难所 `camp`（第二版） | zombie-gold-survival-v2 的本地字段，结算防重复 | 尚未扩展宿主协议，需要服务端定义居民、零件、支援和行动收据 |
| 金币 `wallet` | localStorage | 以服务器为准，启动时 `wallet()` 拉取，每关 `runResult` 后服务器加 |
| 关卡进度 `cleared / next` | 本地 | 建议服务器存一份，换机不丢 |
| 道具 `items` | 本地 | 服务器存，与捕鱼共用 |
| 试玩数据、画质、震动开关 | 本地 | 保持本地 |

## 5. 数据事件

| 事件 | 字段 | 用途 |
|---|---|---|
| `session_start` | `connected`、`ua` | 打开次数、机型 |
| `level_start` | `code`、`ch` | 每关进入人数 |
| `level_end` | 同 `runResult` | 通过率、失败原因、金币产出 |
| `boss_slam` | `code`、`lost`、`dodged` | Boss 砸地有没有教会玩家躲 |
| `item_use` | `item` | 道具消耗 |
| `fishing_start` / `fishing_end` | `wallet`、`items` / `shots`、`spent`、`won`、`kills`、`boss`、`ms` | 跑关到捕鱼的转化、捕鱼留存 |

本地的「试玩数据」面板会继续记录开始、通过、失败、立刻重开、中途退出和帧率，复制出来就是表格，可以在接入数据平台之前先用。

## 6. 当前边界

以上方法名与旧版保持兼容；内部 fish、torpedo 等键是协议/代码键，界面已换题材。没有接入真实主 App 或服务器，本轮只验证本地回退。主游戏升级、云进度、支付和二星不在本轮交付范围。

Spine、3D 道具、粒子和音频的来源记录见 assets/CREDITS.md；完整运行文件由 tools/manifest.py 收集，不沿用旧版模型包体估算。性能需另做真机验收，浏览器自动驾驶通过不代表低端设备性能达标。
